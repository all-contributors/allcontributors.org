The All Contributors specification describes how an open source project recognizes the people who contribute to it, in a way that values every kind of contribution and not only code. This page lists what a project has to do to follow it, and what it can add. The [app](/en/app) and the [CLI](/en/cli) write the table in this format for you, so this page is mostly useful when you want to know why the table looks the way it does, or when you maintain it by hand.

<ThemedImage name="contributors-table" alt="A contributors table in a README with avatars, names and emojis." />

## Mandatory

A project follows the specification when it does the three things below.

### Show a contributors section

The project lists all of its contributors in a "Contributors" section of a prominent place in its repository documentation. In most projects that place is the `README.md`.

When a project has so many contributors that the README becomes unwieldy, it can move the list to a `CONTRIBUTORS` file in the top level of the repository. The README should then link to that file under its "Contributors" heading, so that the list stays easy to find. [Move the table to another file](/en/app/guides/move-the-table) shows how to do this with the tools.

### Format the list as a table

The list is a table with the following information about each contributor:

- Their name.
- A link to a page where visitors can learn more about them. The contributor chooses this page, or the project does, so it can be a personal website, a profile or anything else suitable.
- An indication of what they contributed, as text or as an icon, taken from the contribution categories and their [emojis](/en/project/specification/emoji-key). The indication links to the category.

The list can run over several rows, and each row is technically its own table. The order of the contributors doesn't matter to the specification, so a project can order them any way it likes.

### Include every kind and level of contribution

A contributor is anyone who contributes to the project in any of the contribution categories, at any level. The specification is inclusive by definition, and it recommends against leaving someone out because their contribution seems small.

A project that deviates from this, either by using categories of its own or by requiring a minimum level of contribution before someone counts as a contributor, documents its definition in its `CONTRIBUTING` file or another prominent public document at the top level of the repository. A project that wants to show how much someone contributed can use indicators of effort within the list, as long as the list still includes everyone. The specification doesn't define such indicators, so they are up to the project.

## Optional

Projects are encouraged to go a little further:

1. Include the avatar of each contributor. The specification recommends it, and the tools add avatars by default.
2. Link the contribution indicator to the pages that show the contribution, such as the commits for code or the issues for bug reports. This gives visitors more information about what the person did.

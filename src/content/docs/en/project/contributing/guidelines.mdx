All Contributors is maintained by volunteers, and help of every size is welcome, from fixing a typo to reviewing a feature. This page helps you find out how to get started. Everyone who contributes is expected to follow the [code of conduct](/en/project/contributing/code-of-conduct).

## Ways to help

There are many ways to contribute, so pick the kind of work that you like most:

- Improve these pages, for example by fixing a mistake, clarifying an explanation or adding something that's missing. ["Improve the documentation"](/en/project/contributing/documentation) explains how to make changes and preview them locally.
- Translate the pages into your language with Crowdin, which doesn't require you to know Git. ["Translate the documentation"](/en/project/contributing/translations) explains the steps.
- Fix a bug or add a feature to the bot or the CLI. Each has its own repository, and ["Maintaining the App"](/en/project/maintaining/app) and ["Maintaining the CLI"](/en/project/maintaining/cli) explain how to work on them.
- Report a problem or suggest an idea by opening an issue in one of our repositories. ["Repositories"](/en/project/about/repositories) tells you which one to use.
- Review pull requests, answer questions in issues, or help organize the project. These are contributions too, and very much appreciated.

If you aren't sure where something belongs, open an issue in the [documentation repository](https://github.com/all-contributors/allcontributors.org/issues) and describe what you have in mind.

## Open a pull request

Whichever repository you work in, the process is the same. Fork the repository, create a branch for your change, commit it and open a pull request against the default branch.

Keep the pull request focused on one change, and link the issue it relates to if there is one. For larger changes, open an issue first and discuss the design there, so that you don't spend time on something the maintainers would want to approach differently. The [maintainer processes](/en/project/maintaining/processes) describe what happens to your pull request after you open it.

## Write your commit messages

The projects use [Conventional Commits](https://www.conventionalcommits.org/) for pull request titles and commit messages. Maintainers squash a pull request into one commit when they merge it, and tools build changelogs and releases from those commit messages. A message has a type, an optional scope and a short description:

```none
fix(parser): handle empty strings correctly
docs: update the installation instructions
feat(api): add support for custom headers
```

If you would rather be guided, run `pnpm commit` in this repository or the CLI repository, and answer the questions it asks.

## Add yourself as a contributor

Everyone who helps is recognized in the contributors table of the repository they worked on. Maintainers add you after they merge your pull request, and you can also ask for it yourself by commenting `@all-contributors please add @your-username for doc` on the issue or pull request, replacing `doc` with the type that fits. See [Add contributors](/en/app/guides/usage) for the details.

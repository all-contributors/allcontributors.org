The documentation is written in English and translated by volunteers on [Crowdin](https://crowdin.com/project/all-contributors), a platform where you translate one sentence at a time without touching Git or Markdown files. If you want to help, you don't need any technical setup. You can also [comment on the call for translators](https://github.com/all-contributors/allcontributors.org/issues/143) to say that you are working on a language, or to ask a question.

## Translate strings

<Steps>

1. Open the project

   Go to the [Crowdin project](https://crowdin.com/project/all-contributors), then [sign up](https://crowdin.com/join) or [log in](https://crowdin.com/login), and join the "All Contributors" project.

2. Choose your language

   Click the flag of the language that you want to translate into.

3. Pick a file

   Click a Markdown file that isn't completely translated. The percentage on the right shows how much of each file is done.

4. Write your translation

   Type the translation into the "Enter translation here" field, which belongs to the text in the "Source string" field above it, and click "Save".

</Steps>

If you are a proofreader, you can also approve the suggestions of others, or your own, from the translations section of your language. Click the check mark to approve a suggestion or the trash icon to delete it.

## What to leave untranslated

Some strings in a page aren't text but part of a link, an image or a piece of code. Crowdin shows where a string comes from in its context, as an XPath. A string whose XPath ends in `@href` or `@src` is an address, so leave it exactly as it is, together with anything that is formatted as code. Changing an address breaks the link, and the reader ends up on a 404 page.

![A screenshot of Crowdin showing the string "usage" with the context XPath /ul/li/a[@href], which marks a link address that must stay untranslated.](@/assets/project/translating-xpath.png)

Do translate the explanatory text around code, such as the comments inside a code block, because it helps readers understand the example. Only do that when the translation doesn't change the code itself, since commands and configuration are always written in English.

## When translations go live

Translations are downloaded from Crowdin when the production site is built, so your translation appears on the website with the next production deployment after you save it. Previews of pull requests are built without translations.

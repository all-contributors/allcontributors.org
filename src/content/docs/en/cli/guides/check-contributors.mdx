The contributors table is easy to forget. The `check` command compares the people the host lists as contributors of your repository with the people in `.all-contributorsrc`, so you can see who is missing. It uses the repository named by `projectOwner` and `projectName` in your configuration, and it asks the host for the contributors.

## Run the check

Run the command in the root of your project:

```sh
all-contributors check
```

If everyone matches, the command prints nothing. Otherwise it prints one or two lists:

```text
Missing contributors in .all-contributorsrc:
octocat

Unknown contributors found in .all-contributorsrc:
ghost
```

The first list names people the host knows as contributors who aren't in your configuration. The second list names people who are credited for `code` or `test` but have no commits in the repository. Only those two contribution types are compared against commits, because other types, such as design or documentation, don't show up as commits.

## Compare on the right name

On GitHub the command compares usernames. On GitLab the host lists contributors by their display name, so the command compares those names with the `name` of each entry in your configuration. A GitLab contributor whose name in `.all-contributorsrc` is spelled differently shows up in both lists.

## Use it in automation

The command only prints its findings. It always ends successfully, even when it reports missing contributors, so you can't use the exit code to fail a CI job. To act on the result in a script, read what the command prints.

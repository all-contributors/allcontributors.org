The CLI reads its settings from the `.all-contributorsrc` file in the directory where you run it, the same file the [app](/en/app) uses. Most options are shared between the two tools, and the [app configuration reference](/en/app/reference/configuration) describes all of them in one table, with a column that says which tool reads each option. This page covers what is specific to the CLI.

## Where the file comes from

The CLI looks for `.all-contributorsrc` in the current directory. To use a file elsewhere, pass its path with `--config`:

```sh
all-contributors add jane doc --config docs/.all-contributorsrc
```

The `init` command always creates `.all-contributorsrc` in the current directory, so move the file afterwards if you want it somewhere else.

## Options and flags

Settings in the file win over the same setting on the command line. A flag such as `--contributorsSortAlphabetically` therefore only has an effect when the file doesn't set that option, so put an option you always want into the file and use flags for one-off runs.

If the file doesn't set `repoType`, the CLI uses `github`, and if it doesn't set `commitConvention`, it uses `angular`. For the table, the CLI defaults to `README.md` for `files` and to seven contributors per line.

## Options that only the CLI reads

Two options belong to the CLI and are ignored by the app:

- `commit` turns on automatic commits after `add`. It is `false` unless you set it, and `init` asks whether you want it.
- `commitTemplate` replaces the commit message. [Commit automatically](/en/cli/guides/commit-automatically) shows how.

The options `commitType` and `skipCi` are read by the app only, because the app uses them for the pull request it opens.

Installing the app takes a few minutes. You give it access to the repositories you choose, and you make sure there is a `README.md` for it to work with. Everything else, including the configuration file and the contributors table, can be created by the app itself the first time you ask it to add someone.

<Steps>

1. Install the GitHub App

   Choose the account or organization that owns your repository.

   <LinkButton href="https://github.com/apps/allcontributors/installations/new">Install the GitHub App</LinkButton>

   ![A screenshot of the GitHub page that appears after you click the install button. It lists the accounts and organizations you can install the app on.](@/assets/bot/app-install.png)

2. Choose your repositories

   Select the repositories the app may work in. The app only reacts to comments in repositories you give it access to, and you can change that selection later from the app's configuration page in your GitHub settings.

   ![A screenshot showing how to select repositories for the All Contributors GitHub App.](@/assets/bot/configure-repositories.png)

3. Make sure a `README.md` exists

   Your repository needs a `README.md` in its root, and it can be empty. The app edits the files listed under `files` in your configuration, which is `README.md` by default, and it replies with an error if one of them doesn't exist.

4. Choose how the table is created

   You can let the app create the table, or you can prepare the files yourself. Both are described below.

5. Tell your contributors about it

   Add a line to your `CONTRIBUTING.md` that explains how people can ask to be added, and link to [Add contributors](/en/app/guides/usage).

</Steps>

## Let the app create the table

If your repository has no `.all-contributorsrc` file, the first request creates it for you. The pull request that the app opens in that case contains the new `.all-contributorsrc`, a contributors badge and a contributors section in `README.md`. This is the shortest way to get started, and you can [move the table to another file](/en/app/guides/move-the-table) after you merge that first pull request.

## Prepare the files yourself

If your repository already has an `.all-contributorsrc` file, for example because you started with the [CLI](/en/cli), the app doesn't add the badge or the table itself. It only replaces what sits between a pair of marker comments, so you need to put the markers where you want the table to appear.

The following snippet marks the place for the table. The empty line inside the markers is where the app writes the table:

```markdown
## Contributors

<!-- ALL-CONTRIBUTORS-LIST:START - Do not remove or modify this section -->
<!-- prettier-ignore-start -->
<!-- markdownlint-disable -->

<!-- markdownlint-restore -->
<!-- prettier-ignore-end -->

<!-- ALL-CONTRIBUTORS-LIST:END -->
```

If you want a badge with the number of contributors, add this line wherever the badge should appear. It reads the count from your repository on its own, so replace `projectOwner` and `projectName` with your GitHub account or organization and the name of your repository:

```markdown
[![All Contributors](https://img.shields.io/github/all-contributors/projectOwner/projectName?color=ee8449&style=flat-square)](#contributors)
```

You can also let the app maintain a badge for you by wrapping it in a pair of `ALL-CONTRIBUTORS-BADGE:START` and `ALL-CONTRIBUTORS-BADGE:END` markers. The app replaces everything between them each time it adds a contributor, and by default it writes a badge with a fixed number. [Update the badge](/en/app/guides/update-badge) explains how to make that badge use the same address as the line above.

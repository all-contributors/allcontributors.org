The app and the [CLI](/en/cli) both keep their settings and the list of contributors in a JSON file named `.all-contributorsrc` in the root of your repository. This page describes every option in that file. The last column says which tool reads the option, so you can use the same table whichever tool you work with.

## Options

| Option | Used by | Description | Default |
| --- | --- | --- | --- |
| `projectName` | both | The name of the repository. The app sets it from the repository it runs in. | None, required by the CLI |
| `projectOwner` | both | The user or organization that owns the repository. The app sets it from the repository it runs in. | None, required by the CLI |
| `repoType` | both | The kind of host, either `github` or `gitlab`. | `github` |
| `repoHost` | both | The address of the host. The CLI uses it to reach the API of a GitHub Enterprise or self-hosted GitLab server, and both tools use it in links to commits, issues and reviews. | `https://github.com` or `https://gitlab.com`, depending on `repoType` |
| `files` | both | The files in which the table and the badge are generated. The app accepts up to 25 files. | `["README.md"]` |
| `imageSize` | both | The width and height of an avatar in pixels. | `100` |
| `contributorsPerLine` | both | The number of contributors in one row of the table. | `7` |
| `contributorsSortAlphabetically` | both | Sorts the table by name when `true`. Otherwise people appear in the order they were added. | `false` |
| `linkToUsage` | both | Adds a footer row with a link that shows how to add contributions when `true`. | Off unless set |
| `types` | both | Adds or overrides contribution types. | None |
| `badgeTemplate` | both | A template for the badge between the badge markers. | A badge with a fixed number |
| `contributorTemplate` | both | A template for the cell of one contributor. | The default cell |
| `wrapperTemplate` | both | A template for the table around the rows. | The default table |
| `commitConvention` | both | The commit message style, which the app uses for the pull request title. The CLI accepts `angular`, `atom`, `gitmoji`, `ember`, `eslint`, `jshint` and `none`. | `angular` |
| `commitType` | app | The type in the pull request title, such as `docs` in `docs: add jane as a contributor`. | `docs` |
| `skipCi` | app | Adds `[skip ci]` to the pull request description when `true`. | `true` in a file the app creates, off when the option is missing |
| `commit` | CLI | Commits the changes after `add` when `true`. | `false` |
| `commitTemplate` | CLI | A template for the commit message. | A message such as `docs: Add @jane as a contributor`, with `Update` for someone who is already listed |
| `contributors` | both | The list of contributors. The tools maintain it, and you can also edit it by hand. | `[]` |

Options with a default that says "None" or "Off unless set" aren't written to the file unless you add them. When a file doesn't contain `files`, `commitType`, `commitConvention`, `contributorsPerLine` or `contributors`, the app fills them in with the defaults from the table.

## An example file

A configuration file that the app creates looks similar to the following one. The `contributors` list is empty here, and the tools add an entry for every person:

```json
{
  "projectName": "widgets",
  "projectOwner": "acme",
  "repoType": "github",
  "repoHost": "https://github.com",
  "files": ["README.md"],
  "imageSize": 100,
  "commit": false,
  "commitType": "docs",
  "commitConvention": "angular",
  "contributors": [],
  "contributorsPerLine": 7,
  "skipCi": true
}
```

## Contributors

Each entry in `contributors` describes one person. The tools write the entries, so you rarely need to touch them, but knowing the shape helps when you edit the file by hand:

```json
{
  "login": "jane",
  "name": "Jane Doe",
  "avatar_url": "https://avatars.githubusercontent.com/u/1?v=4",
  "profile": "https://example.org",
  "contributions": ["doc", "code"]
}
```

The `login` is the username on the host, and `name` falls back to the username when the profile has no name. The `profile` is the website on the person's profile if it has one, and the profile page on the host otherwise. Each item in `contributions` is the name of a contribution type, or an object with a `type` and a `url` when that contribution should link somewhere specific.

## Templates

The three template options contain `<%= value %>` placeholders. [Customize the table](/en/app/guides/customize-the-table#change-the-markup) lists the placeholders each template can use.

The app and the CLI don't render templates with the same library, but both accept the `<%= value %>` placeholder syntax that this documentation uses.

You can use the All Contributors Bot to recognize a contribution by creating a comment that mentions (using `@all-contributors`) the Bot. When you mention the Bot in a comment, it reads your comment, extracts both the username of the contributor and the types of contributions that you are asking the Bot to add for them. It then opens a pull request that adds that contributor and their contributions to your project's contributors table.

In this page you will learn:

1. How the Bot parses your comments that mention it
2. Different ways you can phrase that comment
3. What to expect once a comment is submitted.

This page assumes you have already [installed the Bot App (application) in your account and given it access to the repository where you want to use it](/en/app/get-started/installation).

## Ask the Bot to add a new contributor

To acknowledge a new contributor using the Bot, leave a comment on any issue or pull request in your repository that looks like this:

```plaintext wrap
@all-contributors please add @<username> for <contribution>
```

Replace `<username>` with the person's GitHub username. Replace `<contribution>` with a keyword from the [emoji key](/en/project/specification/emoji-key), such as `doc`, `design`, or `bug`.

What happens next depends on whether the person is already in your contributors table:

- **If they're a new contributor,** the Bot opens a pull request that adds them to your contributors table, and replies with:

  ```plaintext wrap
  @<your-username>

  I've put up a pull request to add @<username>! 🎉
  ```

- **If they're already listed,** the Bot opens a pull request that adds the new contribution (a new emoji) to their existing entry. It replies with the same message:

  ```plaintext wrap
  @<your-username>

  I've put up a pull request to add @<username>! 🎉
  ```

- **If they're already listed for every contribution you named,** the Bot doesn't open a pull request. Instead, it replies with:

  ```plaintext wrap
  @<your-username>

  @<username> already contributed before to <contribution>
  ```

The Bot always mentions you at the start of its reply, so you get a notification. In the reply, "a pull request" links to the new pull request so you can review and merge it.

If a pull request to add that person is already open, the Bot adds your request to that pull request instead of opening a new one. In that case, it replies with:

```plaintext wrap
@<your-username>

I've updated the pull request to add @<username>! 🎉
```

## Add several contribution types for the same contributor

To credit one person for more than one kind of work, list the contributions after `for`, separated by commas:

```plaintext wrap
@all-contributors please add @<username> for <contribution>, <contribution>, and <contribution>
```

The Bot replies with the same message as before, no matter how many contributions you name:

```plaintext wrap
@<your-username>

I've put up a pull request to add @<username>! 🎉
```

The pull request title lists the contributions. If you name more than three, the title lists the first two and counts the rest, so it stays short. For example, if you comment `@all-contributors please add @jane for code, doc, design, and bug`, the pull request title will be:

```plaintext wrap
docs: add jane as a contributor for code, doc, and 2 more
```

## Add several people in a single comment

You can also add several contributors in a single comment. The Bot splits your comment into sentences and looks for one person in each sentence, so give each person their own sentence.

End each sentence with a period, question mark, or exclamation point, or put each contributor on a new line. A comma doesn't start a new sentence, so `please add @jane for code, add @tom for design` is read as one sentence and the Bot gets the username wrong. Two usernames in one sentence, such as `please add @jane and @tom for code`, doesn't work either: the Bot only adds the first person.

Both of the following examples work:

```plaintext wrap
@all-contributors please add @jane for code and tests. Please add @tom for design.
```

```plaintext wrap
@all-contributors please add @jane for code and tests
please add @tom for design
```

The Bot opens a separate pull request for each person. It replies once, with a line for each pull request:

```plaintext wrap
@<your-username>

I've put up a pull request to add @jane! 🎉

I've put up a pull request to add @tom! 🎉
```

:::caution[Warning: Merge conflicts are expected when you add several contributors]
Each pull request is built from your default branch, and they all change the same lines in `.all-contributorsrc` and your contributors table. After you merge the first pull request, the others will usually have merge conflicts.

The maintainer team is exploring a solution to this problem but it might take some time to implement as we refresh this tool.

If you don't want to manually resolve the merge conflicts, close the conflicting pull request and delete its branch, then comment again for that person. The Bot opens a fresh pull request from your updated default branch. You can also resolve the conflict by hand.
:::

## Use plain words

You don't need to memorize the exact keywords from the [emoji key](/en/project/specification/emoji-key). The Bot uses natural language parsing to figure out which contribution type you mean, so you can write your request the way you'd normally say it. For example, if you write `infrastructure`, the Bot knows you mean the `infra` keyword. These two comments do the exact same thing. Both add Jane for documentation (`doc`) and infrastructure (`infra`):

```plaintext wrap
@all-contributors please add @jane for docs and infra
```

```plaintext wrap
@all-contributors please add @jane for documentation and infrastructure
```

The Bot understands:

- **Plurals**, such as `bugs` or `tests`
- **Common alternate words**, such as `documentation` for `doc` or `testing` for `test`
- **Two-word phrases**, such as `user testing` or `project management`

If you use a word the Bot doesn't recognize, it skips that word and adds the other contribution types it can find. For example, `please add @jane for docs and cooking` adds Jane for `doc` and leaves out `cooking`.

If the Bot can't find any contribution types in your comment, it doesn't open a pull request. Instead, it replies with:

```plaintext wrap
@<your-username>

I couldn't determine any contributions to add, did you specify any contributions? Please make sure to use valid contribution names.
```

In the reply, "valid contribution names" links to the [emoji key](/en/project/specification/emoji-key). Check it for the words the Bot understands, then try again with a new comment.

## Where the Bot listens for mentions

The Bot only responds to new comments that mention `@all-contributors` (or `@allcontributors`) followed by a space. You can leave that comment on any issue, or in the **Conversation** tab of a pull request.

The Bot won't see:

- **Edited comments.** If you need to fix a typo in your request, write a new comment instead.
- **Comments in a pull request review.** This includes comments on specific lines in the **Files changed** tab, and the summary you write when you submit a review.

:::note[The Bot can't remove contributors]
The Bot only adds contributors and contribution types. To remove someone, edit the `contributors` list in `.all-contributorsrc`, then update the table by hand or with the [CLI's `generate` command](/en/cli/reference/commands#all-contributors-generate).
:::

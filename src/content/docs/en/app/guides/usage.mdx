You recognize a contribution by mentioning the All Contributors Bot in a comment. The bot reads the comment, finds the person and their contributions, and opens a pull request that adds them to your contributor table. This guide assumes that you have [installed the bot](/en/app/get-started/installation).

## Ways to call the bot

Comment on any issue or pull request in your repository:

```plaintext wrap
@all-contributors please add @<username> for <contribution>
```

`<username>` is the person's GitHub username, and `<contribution>` is one of the [contribution types](/en/project/specification/emoji-key), such as `doc`, `design` or `bug`.

The bot listens for `@all-contributors` or `@allcontributors` followed by a space or a line break, in any capitalization. It finds the username after the word `add` or before the word `for`, so keep the `@` in front of it. The rest of the sentence can be phrased freely. Words that aren't contribution types are skipped.

The bot only reads new comments in issues and in the conversation of pull requests. It ignores edited comments and pull request reviews, including comments on lines in the **Files changed** tab, so write a new comment to try again. If the bot doesn't reply, see [Troubleshooting](/en/app/guides/troubleshooting#the-bot-doesnt-reply).

## How the bot replies

The bot mentions you at the start of its reply. If the person is new, or already listed and gets a new contribution, the reply links to a pull request:

```plaintext wrap
@<your-username>

I've put up a pull request to add @<username>! 🎉
```

If a pull request for that person is still open, the bot adds your request to it and replies "I've updated the pull request to add @\<username\>! 🎉". If the person already has every contribution you named, the bot opens nothing and replies "@\<username\> already contributed before to \<contribution\>". [Troubleshooting](/en/app/guides/troubleshooting) lists the other replies.

## Credit several contributions

List the contributions after `for`, separated by commas:

```plaintext wrap
@all-contributors please add @<username> for code, doc, design and bug
```

For more than three contributions, the pull request title names the first two and counts the rest, for example `docs: add jane as a contributor for code, doc, and 2 more`.

## Add several people at once

The bot reads a comment sentence by sentence and adds one person per sentence. End each sentence with a period, question mark or exclamation point, or put each person on a new line:

```plaintext wrap
@all-contributors please add @jane for code and tests.
Please add @tom for design.
```

A comma doesn't end a sentence, so `please add @jane for code, add @tom for design` is read as one request, and two usernames in one sentence, such as `@jane and @tom`, don't work either.

The bot opens a separate pull request for each person and replies once, with a line per pull request.

:::caution[Merge conflicts are expected]
Each pull request is built from your default branch, and they all change the same lines in `.all-contributorsrc` and the contributor table. After you merge the first one, the others usually conflict. To address this, close the conflicting pull request, delete its branch, and comment again to add that contributor. Or you can resolve the merge conflict by hand.
:::

## Use plain words

You don't have to use the exact keyword from the [emoji key](/en/project/specification/emoji-key). These two comments both add Jane for documentation (`doc`) and infrastructure (`infra`):

```plaintext wrap
@all-contributors please add @jane for docs and infra
```

```plaintext wrap
@all-contributors please add @jane for documentation and infrastructure
```

The bot also understands plurals, such as `bugs` or `tests`, and two-word phrases, such as `user testing` or `project management`. A word it doesn't know is skipped. `please add @jane for docs and cooking` adds Jane for `doc` and leaves out `cooking`.

## Remove a contributor

The bot only adds contributors and contribution types. To remove one, edit the `contributors` list in `.all-contributorsrc`, then update the table by hand or with [`all-contributors generate`](/en/cli/guides/usage).
